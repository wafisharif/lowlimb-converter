# Station 3 gates: muscle paths (moment arms and lengths)

Written 2026-10-10, before any Station 3 code existed or had run. A copy was posted to the plan doc (version history
timestamps it) before any run.

**Question:** for every muscle, does the converted MuJoCo model have the same moment arm about every joint the muscle
crosses, and the same musculotendon length, as OpenSim, across the poses a model can take? MyoConverter checks this
itself (Step 2), but with its own code and sampling; this station checks it independently and compares our converter
with MyoConverter's own output on the same poses.

## Models

gait10dof18musc and gait2354 (both passed Station 2). Rajagopal2016 is still at Station 2 and is not run here.

| Column | MuJoCo file | Run in |
| --- | --- | --- |
| MyoConverter (baseline) | `baseline/<model>/<model>_cvt3.xml` (Station 0 output) | MuJoCo 2.3.7 |
| Ours | cvt3 from the full pipeline with the current converter, regenerated by the run script | MuJoCo 3.15 |

## Method (fixed now)

- **Poses:** exactly the Station 2 poses (`station2/osim_reference.py`: 1000 random poses, seed 20261006, plus a
  41-point sweep of every free coordinate; locked coordinates at default; coupled coordinates from their constraint).
  MuJoCo poses are set as in Station 2 (independent joints from the coordinates, dependent joints from their
  joint-equality polynomials).
- **Muscle–coordinate pairs:** for each muscle, the independent coordinates of every joint on the tree path between
  the bodies of its path points (moving and conditional points included), plus any coordinate those joints'
  coordinates are coupled to. A pair is **evaluated** if OpenSim's largest |moment arm| over all poses is ≥ 1 mm;
  others are counted and listed but not scored.
- **OpenSim moment arm:** `Muscle.computeMomentArm(state, coordinate)`. **Length:** `Muscle.getLength(state)`.
- **MuJoCo moment arm:** −dL/dq of the muscle's tendon length, central difference with h = 1e-6 (rad or m) on the
  coordinate, re-solving the dependent joints at q ± h, so moving path points and coupled joints count exactly as
  in OpenSim. **Length:** the tendon length.
- **Errors:** per evaluated pair, RMS and max |moment-arm error| over all poses (mm), and RMS as % of OpenSim's peak
  |moment arm|. Per muscle, RMS and max |length error| (mm).

## Gates

- **M0 THE CHECK IS VALID (every model, both columns):**
  every OpenSim muscle has a MuJoCo actuator of the same name driving tendon `<name>_tendon`; the pose count is
  1000 + 41 × (number of swept coordinates); the largest MuJoCo equality residual is ≤ 1e-9; OpenSim's QErr is
  ≤ 1e-9; and the two moment-arm methods are self-consistent on the first 50 random poses:
  - OpenSim `computeMomentArm` agrees with −dL/dq by central difference (h = 1e-6) within 1e-5 m for ≥ 99% of
    (pose, pair) samples (wrapping can make a few samples non-smooth);
  - MuJoCo −dL/dq with h = 1e-6 and h = 1e-5 agree within 1e-6 m for ≥ 99% of samples.
  If M0 fails, M1 is not evaluated.
- **M1 NOT WORSE THAN MYOCONVERTER (every model):** for every evaluated pair, our RMS moment-arm error is
  ≤ MyoConverter's RMS error on the same pair + 0.1 mm. As the plan allows, a pair that misses this may be
  **listed with a reason**, but only a reason demonstrated by a test (for example: the same error appears with
  MyoConverter's own path geometry swapped in). Unexplained misses fail the gate.

Reported, no gate (the plan sets no absolute moment-arm threshold): every pair's RMS and max error and % of peak,
the number of pairs within 5% of peak and within 2 mm, length errors per muscle, worst muscles, and how MyoConverter's
own Step 2 report compares with this check.

If M1 fails, the model stays at Station 3; the cause is fixed in the converter as its own change (logged, with a
before/after on both models). The gates don't change.
