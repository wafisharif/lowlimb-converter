# Station 2 gates: kinematic check

Written 2026-10-06, before any Station 2 comparison code existed or had run. A copy was posted to the plan doc
(version history timestamps it) before any run.

**Question:** put OpenSim and the converted MuJoCo model in the same pose. Are all bodies in the same place, facing
the same way? Station 0 found that MyoConverter never checked this for the gait models (no markers, so its Step 1
check compared zero points and reported NaN), so there is no MyoConverter number to beat. The gates are absolute.

**MyoConverter's own output.** For the two gait models, the same check is also run on the Station 0 cvt3 files
(`baseline/<model>/`) in MuJoCo 2.3.7, and reported next to ours. No gate; it is the baseline column.

## Method (fixed now)

- **Poses.** 1000 random poses (NumPy `default_rng(20261006)`): every unlocked, independent coordinate drawn
  uniformly from its OpenSim range. Plus one sweep per such coordinate: 41 evenly spaced values across its range,
  all others at their default value. Locked coordinates stay at their default value (that is what OpenSim does,
  and what the converter's lock constraint encodes).
- **OpenSim (reference).** OpenSim 4.6. Set each coordinate without enforcing constraints. Each coupled coordinate
  (CoordinateCouplerConstraint) is set to its constraint function of the independent values. Then realize position
  and read each body's transform in ground.
- **MuJoCo.** Set each independent joint to the coordinate value. Each dependent joint is set from its joint-equality
  polynomial, `y = y0 + Σ aᵢ (x − x0)ⁱ` with x0, y0 from `qpos0` (MuJoCo's definition); with no second joint,
  `y = y0 + a0`. Then run forward kinematics. Mesh geoms are removed before compiling (geometry doesn't affect where
  bodies are; the mesh files aren't committed).
- **Common frame.** MuJoCo poses are expressed in the frame of the MuJoCo body named `ground`, so the converter's
  +90° root rotation doesn't need to be undone by hand.
- **Bodies compared.** Every body in the OpenSim BodySet, matched by name. MuJoCo's extra path-point bodies are not
  bodies in OpenSim, so they're not compared here (muscle paths are Station 3).
- **Errors.** Position error: distance between body origins (mm). Orientation error: angle of R_osimᵀ R_mujoco (deg).

## Gates

- **K0 THE CHECK IS VALID (every model, every pose):** every OpenSim body has a MuJoCo body of the same name;
  every MuJoCo joint is either an OpenSim coordinate or driven by a joint equality; the largest MuJoCo
  equality-constraint residual is ≤ 1e-9 and OpenSim's largest position-constraint error is ≤ 1e-9; poses compared
  = 1000 + 41 × (number of swept coordinates). If K0 fails, K1–K2 are not evaluated.
- **K1 POSITION (every model):** every body origin, in every pose, within **1.0 mm** of OpenSim.
- **K2 ORIENTATION (every model):** every body, in every pose, within **0.5°** of OpenSim.

Reported, no gate: per body mean, RMS and max of both errors; worst pose and coordinate; errors over each sweep;
the MyoConverter-output column for the gait models.

If a model fails K1 or K2, it stays at Station 2. The cause is found and fixed in the converter as its own change
(logged, with a before/after on all three models), and the converted model is regenerated. The gates do not change.

## Expected from reading the code (written before running)

- **gait10dof18musc, gait2354: expect PASS.** No joint has a child-frame offset, and every offset in these files has
  ≤ 4 significant figures, so the converter's `'%.4g'` number formatting (`xml/utils.py`, `vec2str`) loses nothing.
  The knee translations use a quartic fit to OpenSim's spline, which should be well under 1 mm.
- **Rajagopal2016: expect FAIL** below every joint with a child-frame offset (14 joints: knees, ankles, subtalars,
  MTPs, elbows, forearms, wrists). `xml/bodies/Body.py` subtracts the child offset's translation without rotating it,
  and composes the orientations in the opposite order from OpenSim; hinge rotations are also centred at the MuJoCo
  body origin, not the joint's child frame. Size unknown until run.
- The `'%.4g'` formatting also tilts the root by 0.0117° (90° becomes 1.571 rad). Both `ground` and `pelvis` get the
  same tilt, so it cancels in this comparison. It does tilt gravity relative to the model; noted for Station 5.
